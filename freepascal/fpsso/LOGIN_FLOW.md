# เอกสารอธิบายเงื่อนไขและลำดับการทำงานของระบบ Login (fpsso)

ระบบ `fpsso` รองรับการเข้าสู่ระบบผ่าน 4 ช่องทางหลัก โดยแต่ละช่องทางมีเงื่อนไขและกระบวนการตรวจสอบข้อมูล (Authentication Flow & Account Linking) เพื่อยืนยันตัวตนก่อนเข้าใช้งานเครือข่าย (FortiGate) ดังนี้:

---

## 1. Local Auth (ล็อกอินด้วย Username และ Password ปกติ)
เป็นการตรวจสอบสิทธิ์โดยใช้ฐานข้อมูลภายในระบบ (`radcheck_mirror` / RADIUS) โดยตรง

**เงื่อนไขการตรวจสอบ:**
1. ระบบรับค่า `Username` และ `Password` จากหน้าเว็บ
2. นำไปตรวจสอบรหัสผ่านด้วยฟังก์ชัน `LocalRadiusAuth`
3. ตรวจสอบสถานะบัญชี (เช่น วันหมดอายุ, ระงับการใช้งาน) 
4. หากถูกต้องทั้งหมด ระบบจะอนุญาตให้ล็อกอินในชื่อ `Username` นั้นทันที
5. บันทึกประวัติลง `login_history` โดยใช้ `AuthMethod = 'LOCAL'`

---

## 2. ThaID Auth (แอปพลิเคชัน ThaID)
เป็นการล็อกอินผ่านระบบยืนยันตัวตนแห่งชาติ (National Digital ID)

**เงื่อนไขการตรวจสอบ:**
1. ระบบรับ JWT Token จาก ThaID และถอดรหัสเพื่อดึงค่า **`PID`** (เลขประจำตัวประชาชน 13 หลัก)
2. นำเลข `PID` ไปใช้เป็น **`Username`** ในการเข้าสู่ระบบ
3. เรียกใช้ฟังก์ชัน `SSORadiusAuth(PID)` 
   - **กรณีมีบัญชีอยู่แล้ว:** ถ้าระบบพบว่ามี `Username` ที่ตรงกับ `PID` นี้ในฐานข้อมูล ระบบจะเชื่อมโยงเข้าบัญชีนี้ และอัปเดตรหัสผ่านชั่วคราวให้ทันที
   - **กรณีไม่มีบัญชี:** ระบบจะสร้างบัญชีผู้ใช้ใหม่ให้โดยอัตโนมัติ โดยใช้เลข 13 หลักเป็น Username
4. ตรวจสอบสถานะบัญชี (เช่น ถูกแบน หรือรออนุมัติหรือไม่)
5. บันทึกประวัติลง `login_history` โดยใช้ `AuthMethod = 'THAID'`

---

## 3. Google Auth (ล็อกอินด้วยบัญชี Google)
เป็นการล็อกอินผ่าน Google OAuth2 พร้อมระบบ **ผูกบัญชีด้วยอีเมล (Auto Account Linking)**

**เงื่อนไขการตรวจสอบ:**
1. ระบบดึงข้อมูลจาก Google UserInfo ได้แก่ `GoogleID` (sub) และ `Email` (อีเมล)
2. **การผูกบัญชีอัตโนมัติ:**
   - ระบบจะนำ `Email` ไปค้นหาในตาราง `radcheck_mirror` ก่อน
   - **ถ้าพบอีเมลตรงกัน:** ระบบจะดึง `Username` เดิมของบัญชีนั้นมาใช้ล็อกอินให้ทันที (เช่น หากเคยสร้างบัญชีด้วยเลขประชาชน แล้วใส่อีเมลนี้ไว้ ก็จะล็อกอินเข้าบัญชีเลขประชาชนได้เลย)
   - **ถ้าไม่พบอีเมล / ไม่มีอีเมล:** ระบบจะใช้ค่า `GoogleID` (ตัวเลขยาวๆ) ไปสร้างเป็น `Username` บัญชีใหม่แยกต่างหาก
3. เรียกใช้ฟังก์ชัน `SSORadiusAuth` ตาม Username ที่คำนวณได้
4. ตรวจสอบสถานะบัญชี และบันทึกประวัติลง `login_history` โดยใช้ `AuthMethod = 'GOOGLE'`

---

## 4. Provider ID Auth (ล็อกอินผ่านระบบของหน่วยงาน)
เป็นการล็อกอินผ่านเซิร์ฟเวอร์ OpenID Connect (OIDC) ของหน่วยงาน พร้อมระบบ **ผูกบัญชีด้วยอีเมล**

**เงื่อนไขการตรวจสอบ:**
1. ระบบดึงข้อมูลจาก `/userinfo` ของ Provider ID ได้แก่ **`PID`** (จากฟิลด์ `pid` หรือ `sub`) และ **`Email`**
2. **การผูกบัญชีอัตโนมัติ:**
   - คล้ายกับของ Google คือระบบจะนำ `Email` (ถ้ามี) ไปค้นหาในตาราง `radcheck_mirror` 
   - **ถ้าพบอีเมลตรงกัน:** ระบบจะดึง `Username` ของบัญชีนั้นมาใช้ล็อกอิน (ผูกบัญชีเดิมให้)
   - **ถ้าไม่พบ / ProviderID ไม่ส่งอีเมลมา:** ระบบจะบังคับใช้ค่า `PID` (เช่น รหัสพนักงาน) นำไปตรวจสอบหรือสร้างเป็น `Username` บัญชีใหม่
3. เรียกใช้ฟังก์ชัน `SSORadiusAuth` ตาม Username ที่คำนวณได้
4. ตรวจสอบสถานะบัญชี และบันทึกประวัติลง `login_history` โดยใช้ `AuthMethod = 'PROVIDERID'`

---

## เงื่อนไขการตรวจสอบร่วมกัน (Post-Login Validation)
ทุกช่องทางการล็อกอิน เมื่อผ่านขั้นตอนด้านบนมาแล้วจะต้องผ่านด่านตรวจสุดท้าย ดังนี้:
1. **สถานะการเปิดใช้งาน (IsActive):** บัญชีต้องไม่ถูกปิดการใช้งาน หรืออยู่ระหว่างรออนุมัติ (`error=pending`)
2. **Demo Mode Limit:** หากใช้งานในโหมดทดลองใช้ ระบบจะตรวจสอบโควต้าการล็อกอินสูงสุดต่อวันผ่าน `SessionManager.CheckAndRegisterLogin`
3. **Session Update:** ข้อมูลทั้งหมด (Username, AuthMethod, รหัสผ่านชั่วคราว) จะถูกเก็บลงเซสชันเพื่อเตรียมส่งให้ FortiGate ต่อไป
4. **Login History:** ประวัติการเข้าสู่ระบบทั้งหมด จะถูกจดบันทึกไว้เสมอพร้อมกับ IP Address และวันเวลาจริง
